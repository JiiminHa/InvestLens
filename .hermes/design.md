# InvestLens UI Design Guide

## Product surface

InvestLens의 기본 화면은 투자 학습을 탐색하고 기록하는 데스크톱형 작업 공간이다.
시각적 방향은 Obsidian 같은 지식 관리 도구의 밀도와 패널 구조를 참고하되,
특정 제품을 그대로 복제하지 않고 InvestLens의 학습 흐름을 우선한다.

## Core layout

- 전체 화면을 채우는 앱 셸을 사용한다.
- 상단에는 얇은 제목 표시줄 하나만 둔다.
- 제품명은 `InvestLens` 한 번만 표시한다.
- 내부 상태명(`browse`, `learning`, `completed`)을 사용자 UI에 그대로 노출하지 않는다.
- 본문은 왼쪽 탐색기, 중앙 문서, 오른쪽 코치의 3개 패널로 구성한다.
- 패널은 큰 카드와 바깥 여백이 아니라 얇은 구분선으로 나눈다.
- 왼쪽은 테마·과거 노트·렌즈를 탐색하는 영역이다.
- 중앙은 선택한 시장 장면이나 학습 노트를 읽는 주 작업 영역이다.
- 오른쪽은 질문·판단·결정·완료 요약을 다루는 보조 영역이다.

## Sidebar behavior

- 상단 왼쪽과 오른쪽에 각각 사이드바 토글 버튼을 둔다.
- 버튼은 `aria-label`과 `aria-expanded`를 제공한다.
- 데스크톱에서는 두 사이드바를 기본으로 연다.
- 사이드바를 접으면 중앙 문서가 남은 공간을 사용한다.
- 모바일(760px 이하)에서는 두 사이드바를 기본으로 닫는다.
- 모바일 사이드바는 본문 위에 나타나는 drawer로 동작한다.
- 모바일에서 테마나 과거 노트를 선택하면 왼쪽 drawer를 자동으로 닫는다.

## Visual language

- 중립적인 밝은 회색 앱 배경과 흰색 문서 배경을 사용한다.
- 강조색은 보라색 계열 하나로 제한한다.
- 그림자는 모바일 drawer처럼 깊이 구분이 필요한 경우에만 사용한다.
- 목록 항목은 파일 탐색기처럼 촘촘하게 구성한다.
- 큰 border-radius와 독립 카드가 반복되는 대시보드 스타일을 피한다.
- 중앙 제목은 명확하게, 사이드바 제목은 작고 조밀하게 표현한다.
- 긴 텍스트에는 `min-width: 0`, 줄바꿈, overflow 처리를 적용한다.
- 그래프에는 실제 `relatedPastLearning`에 포함된 노드만 표시한다.

## States

- 초기 상태: 중앙에 테마 선택 안내, 오른쪽에 비활성 코치 안내를 표시한다.
- 테마 선택: 중앙에 시장 장면과 수치, 오른쪽에 학습 시작 버튼을 표시한다.
- 학습 중: 오른쪽에 코치 질문, 판단 입력, 결정 선택을 표시한다.
- 완료: 중앙에 관련 학습 그래프, 오른쪽에 학습 요약을 표시한다.
- 과거 노트 선택: 왼쪽과 오른쪽 패널을 다시 만들지 않고 중앙 내용만 변경한다.
- 오류: 예전 페이지형 오류 화면으로 이동하지 않고 중앙 문서 영역에 표시한다.
- 다시 시도: 현재 워크스페이스를 유지한 채 데이터를 다시 불러온다.

## Mock and data integrity

- fixture와 mock 응답을 실제 시장 데이터처럼 보이게 만들지 않는다.
- 상단 상태 표시와 시장 장면 안에서 `개발용 mock 데이터`임을 확인할 수 있어야 한다.
- mock 안내를 숨기는 스타일을 추가하지 않는다.
- 실시간 데이터 연결 전까지 검증되지 않은 숫자를 실제 수치로 표현하지 않는다.

## CSS maintenance

- 워크스페이스 스타일은 `styles.css`의 단일 섹션에서 관리한다.
- 동일 선택자를 뒤쪽 override 블록에 다시 복사하지 않는다.
- 시각 수정 전에 기존 규칙을 고치며, 새 override를 계속 덧붙이지 않는다.
- 디자인 토큰은 `body.ws-open`에 정의된 `--ws-*` 변수를 사용한다.
- 데스크톱, 1100px 이하, 760px 이하의 세 구간만 우선 유지한다.
- 사용하지 않는 클래스와 완전히 중복된 선언을 남기지 않는다.

## Change boundaries

- 시각 변경에서 학습 Skill의 코칭 로직이나 API 계약을 변경하지 않는다.
- UI는 특정 투자 lens를 미리 선택하지 않는다.
- 실시간 주식 API 연결은 UI 변경과 별도 Issue/PR로 분리한다.
- 기존 Golden Path가 깨지는 디자인 변경은 완료로 보지 않는다.

## Required verification

변경 후 아래 항목을 실제 브라우저에서 확인한다.

1. 제목이나 본문 텍스트가 겹치지 않는다.
2. 좌·우 사이드바가 각각 열리고 닫힌다.
3. 데스크톱에서 3개 패널이 독립적으로 스크롤된다.
4. 모바일에서 본문이 먼저 보이고 drawer가 정상 작동한다.
5. 테마 선택부터 학습 완료까지 Golden Path가 동작한다.
6. 완료 그래프의 노드 라벨이 겹치지 않는다.
7. 오류 화면과 다시 시도가 워크스페이스 안에서 동작한다.
8. mock 데이터 표시가 항상 보인다.
9. 콘솔 오류와 실패한 네트워크 요청이 없다.
